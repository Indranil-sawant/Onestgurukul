# O'Nest Gurukul — Deployment Documentation

This document details the configuration, deployment, domain setup, and rollback procedures for the O'Nest Gurukul school website.

---

## 📂 Project Architecture

The website is a **100% static frontend** containing:
- Root HTML files (`index.html`, `about.html`, etc.)
- Styling sheets under `assets/css/`
- Dynamic scripts under `assets/js/`
- Media assets under `assets/img/` and `assets/ONEST/`
- In-memory database content in `db.js`
- Global widget injects (chatbot, search, alert banner) in `onest-global.js`
- Legal notice pages under `legal/`
- SEO templates under `public/`

---

## 💻 Local Development & Serve

To preview the website locally:
1. Since the project contains no build configuration or Node compile dependencies, you do not need to run `npm install`.
2. Serve the directory using any static web server:
   - **VS Code Live Server**: Right-click `index.html` and select **Open with Live Server**.
   - **Python Simple Server**:
     ```bash
     python -m http.server 8000
     ```
   - **Node HTTP Server**:
     ```bash
     npx http-server . -p 8000
     ```
3. Open `http://localhost:8000` in your web browser.

## ☁️ Deployment Procedures

### Option A: GitHub Pages (Recommended / Current)
Since the site is static, GitHub Pages is the simplest hosting solution:
1. Initialize a Git repository in the folder (if not done) and push the code to a private or public GitHub repository.
2. In the GitHub repository settings, navigate to **Pages**.
3. Under **Build and deployment**, select **Deploy from a branch** and set the source branch to `main` (or `master`) and directory to `/ (root)`.
4. Click **Save**. The site will be built and published at `https://<username>.github.io/<repo-name>/` within 1–2 minutes.

### Option B: Netlify or Vercel
For modern deployments with global CDN acceleration and easy environment variables:
1. Connect your GitHub repository to Netlify or Vercel.
2. Set the **Build Command** to: `[leave empty]` (or `echo "Static Site"`).
3. Set the **Publish Directory** to: `. (root)`.
4. Click **Deploy**. Both platforms support instant rollbacks and preview deployments on pull requests.

## 🌐 Domain & DNS Configuration Checklist

When migrating the domain `onestgurukul.in` to point to the live server:

### 1. Web Hosting Records
- **For GitHub Pages**:
  - Configure the **Custom Domain** in the GitHub repository Pages settings to `onestgurukul.in`.
  - Add four `A` records in your registrar's DNS dashboard pointing to GitHub's server IPs:
    - `185.199.108.153`
    - `185.199.109.153`
    - `185.199.110.153`
    - `185.199.111.153`
  - Add a `CNAME` record for `www` pointing to `<username>.github.io`.
- **For Netlify / Vercel**:
  - Add the custom domain inside the hosting dashboard and point the DNS `CNAME` or `A` record to their respective target endpoints.

### 2. HTTPS / SSL Setup
- Secure Socket Layer (SSL) certificates are automatically generated by GitHub Pages (via Let's Encrypt), Netlify, or Vercel.
- Verify **Enforce HTTPS** is ticked in the hosting panel to redirect all HTTP traffic to HTTPS.

### 3. Professional Email Setup (MX & Security TXT)
Ensure that the official school emails (`info@onestgurukul.in`) are active:
- Configure DNS `MX` records to point to your email provider (e.g. Google Workspace, Zoho Mail).
- Add security `TXT` records to prevent email spoofing:
  - **SPF**: `v=spf1 include:_spf.google.com ~all` (example for Google).
  - **DKIM**: Add the TXT selector record provided by your email host.
  - **DMARC**: Add `_dmarc.onestgurukul.in` with policy details.

## 🔄 Rollback Procedure

If a bug is discovered post-deployment, trigger a rollback immediately:
- **Git Reversion**:
  1. Identify the last stable commit ID using your commit history.
  2. Revert the repository to the stable commit:
     ```bash
     git revert HEAD
     # Or reset to specific stable hash
     git reset --hard <stable-commit-hash>
     git push origin main --force
     ```
- **Hosting Dashboard**: Both Netlify and Vercel support rolling back with a single click inside the deployments panel, reverting the routing instantly.
